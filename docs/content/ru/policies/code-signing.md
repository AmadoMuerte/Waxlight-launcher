# Политика подписи кода

Правила подписи Windows-артефактов Waxlight через программу SignPath Foundation.

***Free code signing provided by SignPath.io, certificate by SignPath Foundation.** Каноническая версия: [docs/CODE_SIGNING_POLICY.md](https://github.com/AmadoMuerte/Waxlight-launcher/blob/main/docs/CODE_SIGNING_POLICY.md).*

Политика применяется к Windows-артефактам релизов Waxlight. Релизы, опубликованные до активации подписи SignPath Foundation, могут быть неподписанными.

## Проект и репозиторий

- Проект: **Waxlight Launcher**
- Репозиторий: [github.com/AmadoMuerte/Waxlight-launcher](https://github.com/AmadoMuerte/Waxlight-launcher)
- Лицензия: GNU GPL v3.0
- Мейнтейнер: [AmadoMuerte](https://github.com/AmadoMuerte)

Подписываться через подписку Waxlight в SignPath могут только артефакты, собранные из исходного кода и скриптов этого репозитория. Подписка не используется для чужих проектов, приватных/проприетарных компонентов или апстрим-бинарников, выдаваемых за бинарники Waxlight.

## Роли

| Роль | Кто |
| --- | --- |
| Авторы / коммитеры | AmadoMuerte |
| Ревьюеры | AmadoMuerte — ревьюит изменения от контрибьюторов без commit-доступа |
| Аппруверы | AmadoMuerte — вручную проверяет и подтверждает каждый запрос на подпись |

Текущая схема с одним человеком не даёт независимого ревью и подтверждения. Опубликованные условия SignPath требуют наличия ролей, но явно не требуют разных людей. При появлении дополнительных доверенных мейнтейнеров документ будет обновлён. Перед использованием SignPath мейнтейнер вручную проверяет MFA у всех участников репозитория и команды SignPath.

## Ревью и подтверждение

- Вклад от пользователей без commit-доступа мержится только после ревью мейнтейнера.
- Релизные скрипты, GitHub Actions, упаковка, изменения зависимостей и конфигурация подписи ревьюятся так же тщательно, как код приложения.
- Каждый запрос на подпись требует ручного подтверждения аппрувером.
- Подпись привязана к проверяемой автоматической сборке из публичного репозитория; локально собранные или подменённые бинарники не подписываются.

## Происхождение сборок

Windows-релизы собираются из тегированного коммита публичного репозитория. GitHub Actions забирает тег на Windows-раннере, собирает артефакты, валидирует их метаданные и загружает как CI-артефакты. Публикующая джоба скачивает эти артефакты, генерирует `SHA256SUMS` и прикрепляет финальные файлы к релизу. После подтверждения в SignPath на подпись отправляются только эти CI-артефакты.

## Правила артефактов

Планируемое покрытие подписью:

1. исполняемый файл Waxlight до упаковки в portable-архив или установщик;
2. Windows-установщик после упаковки;
3. будущие дополнительные исполняемые файлы Waxlight — только после добавления в ревьюированную конфигурацию артефактов.

Неподписанные апстрим-компоненты могут включаться там, где это разрешено политикой SignPath Foundation, но Waxlight не подписывает апстрим-бинарники как свои.

## Метаданные файлов

Конфигурация SignPath принудительно проверяет метаданные подписываемых бинарников: product name должен указывать **Waxlight Launcher**, версии файла/продукта внутри релиза используют единое Windows-значение версии. Релизная сборка валидирует exe, установщик и exe внутри portable-архива до публикации; пайплайн после подтверждения дополнительно проверяет Authenticode каждого подписанного артефакта.

Windows-пререлизы используют `alpha.N`, `beta.N` или `rc.N`; числовая ревизия резервирует отдельные диапазоны для каналов, чтобы `beta.1` и `beta.2` не получили одинаковую версию файла.

## Проверка пользователем

> [!NOTE] Всегда проверяйте конкретный файл
> Присутствие релиза на GitHub само по себе не доказывает Authenticode-подпись. Проверяйте подпись конкретного скачанного артефакта. Релизы до активации SignPath могут легитимно быть неподписанными.

О различии SHA-256 и Authenticode читайте на странице [«Обновления лаунчера»](../features/updates.md). О проблемах безопасности, связанных с происхождением релизов и подписью, сообщайте приватно по процессу из [политики безопасности](./security.md).
